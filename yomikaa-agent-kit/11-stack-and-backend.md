# 11 Production stack: Next.js, NestJS, Prisma, Supabase, Tailwind

This page **replaces** the localStorage persistence and the "verbatim stylesheet" rule from the earlier pages for the real project. Everything the user sees must still match `reference/yomikaa-reference.html` exactly (pages `01` to `10` define what that is). Only *how it is built* and *where the data lives* change.

| Layer | Choice |
|---|---|
| Frontend | Next.js (App Router), React, TypeScript, Tailwind CSS v4 |
| Backend | NestJS (TypeScript), REST under `/api/v1` |
| ORM | Prisma |
| Database and auth | Supabase (Postgres, Supabase Auth) |
| Tooling | pnpm workspaces, Zod, TanStack Query, Vitest, Jest + supertest, Playwright |

Use the latest stable release of each at build time and pin them in the lockfile. Do not add other libraries.

## 2. Database (Prisma on Supabase Postgres)

`apps/api/prisma/schema.prisma`:

```prisma
generator client { provider = "prisma-client-js" }
datasource db {
  provider  = "postgresql"
  url       = env("DATABASE_URL")   // pooled connection, used at runtime
  directUrl = env("DIRECT_URL")     // direct connection, used by migrations
}

enum NoteKind     { Essay Snippet Note Link }
enum JournalPart  { life work }
enum TicketStatus { todo prog rev block done }

model Note {
  id        Int      @id @default(autoincrement())   // public id; also the chronology tie-break
  title     String
  kind      NoteKind
  excerpt   String                                    // computed by the server, never trusted from the client
  body      String[]                                  // paragraphs
  margin    String?
  url       String?                                   // Link notes only, http(s)
  date      DateTime @db.Date                         // local calendar date chosen by the client
  isSample  Boolean  @default(false)                  // the 12 seeded notes: read-only, no Edit link
  tags      Tag[]
  createdAt DateTime @default(now())
  updatedAt DateTime @updatedAt
  @@index([date(sort: Desc), id(sort: Desc)])
}

model Tag {
  id    Int    @id @default(autoincrement())
  slug  String @unique                                // ^[a-z0-9]+(-[a-z0-9]+)*$
  notes Note[]
}

model JournalDay {
  id        Int            @id @default(autoincrement())
  ownerId   String         @db.Uuid                   // Supabase auth user id
  date      DateTime       @db.Date
  entries   JournalEntry[]
  updatedAt DateTime       @updatedAt
  @@unique([ownerId, date])
}

model JournalEntry {
  id        Int         @id @default(autoincrement())
  dayId     Int
  day       JournalDay  @relation(fields: [dayId], references: [id], onDelete: Cascade)
  part      JournalPart
  position  Int                                       // order within the part
  startTime String      @default("") @db.VarChar(5)   // "HH:MM" or ""
  endTime   String      @default("") @db.VarChar(5)
  text      String      @default("")
  @@index([dayId, part, position])
}

model Ticket {
  id        String       @id @db.Uuid                 // generated by the client (crypto.randomUUID), upserted
  ownerId   String       @db.Uuid
  key       String       @default("")
  title     String       @default("")
  note      String       @default("")
  status    TicketStatus @default(todo)
  workedOn  DateTime     @db.Date
  createdAt DateTime     @default(now())
  updatedAt DateTime     @updatedAt
  @@index([ownerId, createdAt(sort: Desc)])
}

model Draft {
  ownerId   String   @id @db.Uuid                     // one Write draft per owner
  data      Json
  updatedAt DateTime @updatedAt
}
```

- **Seed** (`prisma/seed.ts`): inserts the 12 sample notes from `08` verbatim with `isSample = true` and their tags, in the original order so ids ascend with it. Idempotent (skip when samples exist).
- **Row Level Security:** enable RLS on every table and add **no policies**. The API connects with a privileged Postgres role (bypasses RLS) so it still works, while Supabase's auto-generated Data API with the public anon key can read nothing. Do not expose these tables through the Data API.
- **Connection strings:** use the pooled string for `DATABASE_URL` and the direct string for `DIRECT_URL`, following Supabase's current Prisma guidance. Migrations run only with `prisma migrate deploy` (CI/production) and `prisma migrate dev` (local).
- Rules from `08` still apply: sample notes are read-only, no delete for notes, ticket and journal rows that become unused are removed, never stored blank.

## 3. Authentication and visibility

One owner, no sign-ups. In the Supabase project disable public sign-ups and create the owner user; set `OWNER_USER_ID` (and optionally `OWNER_EMAIL`) in the API env.

| Area | Visitors (not signed in) | Owner |
|---|---|---|
| Home, Index, Reader, Random, note lists, tags | read | read |
| Write (create and edit notes) | not available | full |
| Journal, Tickets, Draft | not available, never returned | full |

- API: a global `OwnerGuard` rejects everything by default; routes marked `@Public()` (note and tag reads, `/health`) are open. The guard verifies the Supabase access token (`Authorization: Bearer ...`) against the project's JWKS and requires `sub === OWNER_USER_ID`. 401 if missing or invalid, 403 if a valid user is not the owner.
- Web: sign in with Supabase Auth (email magic link or one-time code) using `@supabase/ssr` so the session persists in cookies. Add one new, unlinked page `/login`: a single `megain` email input (placeholder `your email`) and a `.steps`-style `Send link` button, with messages in the Write toast style. No other new UI.
- Visitor nav shows only **Index** and **Random** (plus the wordmark). The owner sees all five items exactly as in `02`. Visitors never see Write, Journal or Tickets, and never see the footer `N days journaled` (the stats endpoint returns it to the owner only).
- Security basics: Helmet; CORS allowlist limited to `WEB_ORIGIN`; request body limit 256 KB; throttling on all routes (mutations stricter); Zod `.strict()` on every body; never log tokens or journal text.

## 4. API contract (`/api/v1`, JSON)

Field names match the reference (`ex`, `m`, `body`) so the UI port needs no mapping. Dates are `YYYY-MM-DD` strings. Validation lives in `packages/shared` (Zod) and is used by both apps.

**Notes**
| Method and path | Auth | Body or query | Result |
|---|---|---|---|
| `GET /notes` | public | optional `q`, `kind`, `tag`, `sort` (same semantics as `04`) | `Note[]` (all, newest first by `date`, `id`) |
| `GET /notes/:id` | public | | `Note` |
| `POST /notes` | owner | `{ title, kind, tags[], date, body[], m?, url? }` | `201 Note` |
| `PATCH /notes/:id` | owner | same fields except `date` | `Note`; `403` for sample notes |

`Note` = `{ id, title, kind, tags: string[], date, ex, body?: string[], m?, url?, sample: boolean }`. The server computes `ex` with the shared excerpt function (140 chars plus `...`), enforces the `06` validation rules (title or `Untitled`, body required unless a Link with a URL, Link needs an `http(s)` URL), slugifies tags, connects or creates tags, and deletes tags left with no notes. No delete endpoint.

**Tags and stats**
- `GET /tags` (public) returns `[{ slug, count }]` alphabetical (drives shelves and the marquee).
- `GET /stats` returns `{ notes }` publicly and `{ notes, journalDays }` for the owner.

**Journal (owner)**
- `GET /journal/months/:ym` returns `{ days: { "YYYY-MM-DD": { life: Entry[], work: Entry[] } } }` for that month (calendar dots and the list).
- `GET /journal/years/:y/counts` returns `{ "YYYY-MM": number }` (month chip counts: days with at least one entry).
- `GET /journal/days/:date` returns `{ life: Entry[], work: Entry[] }` (empty arrays when none).
- `PUT /journal/days/:date` with `{ life: Entry[], work: Entry[] }` replaces the day in one transaction (delete existing entries, insert in order with `position`). The server re-applies `used` (text, or both times) and deletes the day when nothing remains. Returns the normalized day.
- `Entry` = `{ from: "HH:MM" | "", to: "HH:MM" | "", text: string }`; the server validates `HH:MM` and caps text length (for example 5000).

**Tickets (owner)**
- `GET /tickets` returns `Ticket[]` newest created first. `Ticket` = `{ id, key, title, status, date, note }` with `status` in `todo | prog | rev | block | done`.
- `PUT /tickets/:id` upserts by the client-generated id. If the ticket is not **used** (key, title and note all empty) it is deleted if it exists and nothing is created (`204`). Otherwise `200 Ticket`. Future dates are rejected.
- `DELETE /tickets/:id` returns `204`.

**Draft (owner)**
- `GET /draft` returns `{ id, title, kind, tags, body, m, url } | null`; `PUT /draft` stores it; `DELETE /draft` clears it (File it and Start over).

**Errors:** `{ statusCode, message, errors? }`; validation failures are `400` with per-field messages. The Write validation messages in `06` are produced by the **client** before calling the API (exact text unchanged); the API is the second line of defense.

## 5. Web data layer

- **Typed client** `lib/api.ts` wraps `fetch`, attaches the Supabase access token, and parses with the shared Zod schemas. **TanStack Query** holds server state.
- **First paint:** Home, Index and Reader data come from public endpoints, fetched on the server in the page and passed as `initialData`, so the first render matches the reference (notes already present). Owner views load client-side.
- **Index filtering and highlighting stay client-side.** Load `GET /notes` once and filter with the shared `matchQ`, so typing is instant and the FLIP animation, count tween and highlight behave exactly as in `04`. The `q`, `kind`, `tag`, `sort` query parameters exist for future scale and must return identical results.
- **Curtain and data:** start a view's fetches when navigation begins (during the 560ms cover). The swap happens when the cover has finished and the data has settled (never wait more than 1500ms). Views therefore appear fully populated at uncover, with no skeletons or spinners.
- **Autosave** (`useAutosave`) keeps the reference debounces: Write draft 700ms, Journal 600ms, Tickets 500ms. State updates locally first (typing never waits on the network). Each resource has **one request in flight**; changes made meanwhile are coalesced and sent after it returns (latest wins), so a slow response can never overwrite a newer edit. The `Saved` flash fires on a successful response.
- **Failure:** if a save fails, the `saved` slot shows `Not saved` (same style, stays visible) and retries with backoff 1s, 2s, 4s up to 30s; the next success flashes `Saved` as usual. Warn with `beforeunload` while unsaved changes exist. When the tab is hidden, flush pending saves with `fetch(..., { keepalive: true })`.
- **File it:** `POST /notes`, then clear the draft, invalidate notes, tags and stats, show `Filed.` and open the Reader after 500ms, as in `06`. Editing uses `PATCH`.
- **Tickets:** create ids with `crypto.randomUUID()` when `Add ticket` is pressed; blank rows exist only in the UI until they are used; two-step Remove calls `DELETE` on the second click.
- **Routing:** keep the single shell with the view state machine and the curtain. Mirror views in real paths (`/`, `/index`, `/write`, `/journal`, `/tickets`) through one optional catch-all route `app/[[...view]]/page.tsx`, with the Reader at `/n/[id]` for shareable note links. Navigation uses `history.pushState`; browser back and forward run the same curtain as a nav click. The hash approach in `00` is superseded.

## 6. Shared package (`packages/shared`)

Pure, framework-free, unit-tested, imported by both apps so rules never drift:
- Zod schemas and inferred types for Note, Entry, Ticket, Draft and every request body.
- `slug`, `matchQ`, `excerpt` (140 plus `...`), `readingMinutes`, chronology numbering.
- `toMin`, `spanMin`, `fmtDur`, `partMin`, `usedEntry`, `usedTicket`.
- Date helpers (`key`, `today`, `fmt`) using **local** dates; the client always sends the date, the server never derives "today" from its own timezone.

## 7. Tailwind CSS (visual fidelity rules)

Tailwind is the styling method, not a license to restyle. The pixel result must be identical to the reference (same screenshots, same computed styles).

1. **Tokens** in `styles/globals.css` with Tailwind v4's CSS-first `@theme`, using the exact values from `01`:
   ```css
   @import "tailwindcss";
   @theme {
     --color-bone: #eeebe3;  --color-paper: #f7f5ef;  --color-ink: #121110;
     --color-mute: #66635b;  --color-signal: #ff4a1c; --color-line: rgba(18,17,16,.16);
     --font-disp: var(--font-instrument-serif), Georgia, "Times New Roman", serif;
     --font-read: var(--font-newsreader), Georgia, serif;
     --font-mono: var(--font-dm-mono), ui-monospace, Menlo, monospace;
     --ease-expo: cubic-bezier(.16,1,.3,1);   /* reference --ease  */
     --ease-inout: cubic-bezier(.7,0,.2,1);   /* reference --ease2 */
   }
   :root { --pad: clamp(20px,4vw,56px); }
   @custom-variant tablet (@media (max-width: 900px));
   @custom-variant phone  (@media (max-width: 600px));
   ```
   Do not use Tailwind's default palette, spacing scale or breakpoints for design values. Only the two breakpoints above exist (`tablet:` and `phone:`). Use arbitrary values for exact numbers (for example `text-[clamp(44px,8vw,120px)] leading-[.95] tracking-[-.02em]`, `duration-[560ms]`, `ease-expo`).
2. **Fonts** through `next/font/google`, exposed as the CSS variables above (`02`/`00` list the weights).
3. **Utilities first** for layout, spacing, typography, borders and colors. **Component classes** (`styles/components.css`, `@layer components`, using `@apply` where convenient) for the patterns utilities cannot express cleanly: the grain overlay (`body::after`), the blended top bar, nav underline draw, curtain, cursor, peek card and orb, hero letter animation and its keyframes, marquee, parent-hover row dimming (`.idx:hover .row`), the reader clip-path sheet, the Write dock visibility (`#write.on .dock`, use a `data-on` attribute), `mark`, `::selection`, scrollbar hiding. Keep the reference class names for these so the selectors and `useCurtainRouter`, `useCursor` and friends can target them.
4. **Preflight:** keep it, then re-apply the reference's base rules (`box-sizing`, button and input resets, `body` font and background, `-webkit-font-smoothing`, `html{-webkit-text-size-adjust:100%}`) in `@layer base`, so form controls and buttons render exactly like the reference.
5. **No component libraries** (no shadcn, Radix, Headless UI, UI kits) and no animation library. Animation remains CSS plus the Web Animations API plus one `requestAnimationFrame` loop.
6. **Keep ids, `aria-*`, roles and `data-*` hooks** from the pages (`#q1`, `#wt`, `#tlist`, `data-go`, ...) so tests and accessibility behave identically.
7. Light theme only: no `dark:` variants anywhere.

## 9. Scripts and local development

Root `package.json` scripts: `dev` (runs web and api in parallel), `build`, `lint`, `typecheck`, `test`, `db:migrate`, `db:seed`, `db:studio`. Local Postgres: the Supabase CLI (`supabase start`) or a Postgres container; point `DATABASE_URL` and `DIRECT_URL` at it, run `db:migrate` then `db:seed`.

## 10. Testing

- **Shared (Vitest):** everything in `09` section 5 (slug, matchQ, fmt/key, excerpt, chronology, calendar blanks), plus journal time math (22:00 to 01:30 is 3h 30m; start-only rows are unused) and ticket `used` rules.
- **API (Jest + supertest, disposable database):** public reads work without a token; every owner route returns 401 without a token and 403 for a non-owner token; sample notes reject `PATCH`; excerpt and tag handling; Link validation; `PUT /journal/days/:date` replaces entries in order and deletes empty days; ticket upsert, unused-ticket deletion and future-date rejection; stats hide `journalDays` from visitors; validation errors are `400`.
- **End to end (Playwright):** the checks in `09` section 5 against the full stack (web, api, local Supabase) signed in as the owner, plus: a visitor sees only Index and Random and gets redirected from `/write`; saves persist across reload and across a second browser context; a failed save (route blocked) shows `Not saved` then recovers.
- **Visual diff** versus the reference is unchanged (`09` sections 5 and 7), and must be run with real seeded data.

## 11. Deployment

Web (Next.js) on a Next-capable host such as Vercel; API (NestJS, long-running Node process or container) on any Node host such as Railway, Render or Fly; database and auth on Supabase. Run `prisma migrate deploy` as a release step before the API starts. Set `WEB_ORIGIN` to the web app's origin. Add a `GET /health` check (public) that also verifies the database connection.

## 12. Allowed deviations from the reference

These are the **only** intentional differences, and each must be listed in `DEVIATIONS.md`:
1. Visitors see a reduced nav (Index, Random) and no journal count in the footer.
2. The `/login` page.
3. The `Not saved` state when a save fails.
4. Real URLs instead of reloading to Home (`pushState`, `/n/[id]`).
5. The reader focus trap and the other invisible accessibility fixes already allowed in `09`.

Everything else (fonts, colors, spacing, easing, durations, copy, layout, behavior) matches the reference exactly.
